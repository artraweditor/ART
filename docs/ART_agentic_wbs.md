# ART Agentic Pipeline — 실행 WBS

**버전**: v2.5 (2026-09-02)
**기간**: 2026-09-01 (화) ~ 2026-11-21 (토) · 12주
**팀**: 3인 (팀장 · 팀원 A · 팀원 B) — 역할 구분 없이 두 서비스에 전원 참여, 태스크 단위로 분담

**이번 개정**: 9/1~9/11의 선행 작업은 아래 8개 태스크와 담당·일자로 확정한다. A-03의 선행 `.arp` 스키마 작업은 제거하고, 필요한 키 선택과 제약 정의는 A-18의 실제 프로필 생성에 포함한다. A-04는 RawPedia 영문 원문만 수집하며, Chroma는 고정한다. 수집 문서 기반 질문셋을 먼저 만들고, RawPedia와 정제된 GitHub 문서를 함께 청킹해 임베딩 모델을 비교한다. 청킹 규칙·직렬화 형식·임베딩 후보는 실험 시작 전에 미리 정하지 않는다. 선정 결과는 9/11에 A-09의 실제 벡터DB 적재·검색 구현에 적용한다. GitHub 원문과 벡터DB의 주 1회 증분 갱신은 이 초기 흐름 뒤에 같은 정제·청킹 규칙으로 처리한다. LangGraph는 이 구간에서 상태·노드·전이 규칙을 설계하고, 구현·경로 분기 검증은 후속 A-13 (2/2)에서 한다. A-05와 A-11의 별도 평가 QA 작성은 제거하며, T23은 고정 질문셋과 최종 실행 기록으로 RAGAS를 계산한다. A-06 데이터 신청은 [FiveK 공식 배포](https://data.csail.mit.edu/graphics/fivek/)가 직접 다운로드 방식이므로 제거하고, WBS 서브셋의 확보·정합 확인은 B-01에서 수행한다. A-19 사진 특성 추출은 소비처인 A-18 직전 W4에 둔다.

## 1. 목적 선언

> **질문에는 답하고, 부탁에는 보정된 이미지로 응답하는 ART 마스터 에이전트.**
> 지식원 2개 — 문서(RawPedia·Issues)와 전문가 사례(FiveK) / 액추에이터 1개 — .arp 프로필 생성 → ART-cli 렌더링.
> 모든 태스크는 이 선언에 소급된다: "이 태스크가 왜 있는가?"의 답은 항상 여기로 회귀한다.

**역할 분담 원칙**: ④ = 루프 실증(요청 → 프로필 → 실물 이미지), ① = 품질·근거(전문가 사례 기반 값 + 정량 벤치마크). ④의 산출물은 "손볼 수 있는 시작점 프로필"이지 전문가 품질이 아니며, 품질 벤치마크는 ①의 SSIM/LPIPS/ΔE가 담당한다.

## 4. 서비스 정의·사용 시나리오

### ④ ART Master Agent (문서 Q&A + 프로필 생성) — 9월

| 시나리오 단계 | 사용자 발화 | 시스템 동작 | 대응 WBS |
|---|---|---|---|
| 1. 사용법 질문 | "사진이 노래요. 어디부터 손대야 하나요?" | 처리 경로 분기 → 쿼리 재작성 → RawPedia 검색 → 리랭킹 → 근거 인용 답변 | A-13~A-17 |
| 2. 실행 요청 ← 루프 발동 | "그거 그냥 해줘. 이 사진이요." | 사진 특성(EXIF·히스토그램) → .arp 생성(스키마·PPVERSION 검증) → ART-cli 렌더링 → 파라미터 표+근거+before/after | A-18~A-20 |
| 3. 대화형 재조정 | "조금만 더 밝게" | 프로필 세션 보관 → 증분 수정 → 재렌더링 | A-21 |
| 4. 문제 해결 | "렌더링하면 까져요" | GitHub Issues·Discussions 검색 → 동일 보고 이슈 + 해결책 | A-10 |

평가: RAGAS (context precision/recall, faithfulness) — T8-1에서 고정한 질문 15개와 원문 문서 ID·근거 절, 최종 실행 기록을 사용.

### ① 사례 기반 보정 추천 — 10월~11월

- **목적**: RAW 편집 진입장벽(슬라이더 수십 개)을, 사진 특성 + 스타일 요청 → 전문가 사례 근거와 함께 시작 프로필로 해소.
- **파이프라인**: FiveK 서브셋 → Lightroom→arp 매핑 → 스타일 태깅 → 씬+스타일 유사 사례 검색(top-k) → 근거 기반 파라미터 생성.
- **데이터 원칙**: 평가 기준 = **Expert C** (비교가능성), 검색 코퍼스 = **전문가 5인 전체** (스타일 다양성) — 용도 분리. **코퍼스/평가셋 hold-out 분리 필수** (같은 사진이 코퍼스와 평가에 겹치면 검색이 정답을 베끼는 꼴이 되어 지표가 무효화됨).
- 평가: ART-cli 렌더링 → hold-out Expert C 대비 SSIM/LPIPS/ΔE + 검색 단계 context precision/recall + 자유형 스타일 평가셋 30~50개.

### 기술 스택

LangGraph (오케스트레이션) · Chroma · ART-cli (렌더링·프로필 검증) · RAGAS · SSIM/LPIPS/ΔE · (조건부) VLM 캡션 — RunPod
