# ART 기반 Agentic AI 포트폴리오 프로젝트 기획안

**도메인**: RAW 사진 편집 툴 [ART](https://github.com/artraweditor/ART) (RawTherapee 파생, `.arp` 프로필 포맷)
**기간**: 4개월 (일 2~3시간, 총 예산 약 250~300시간)
**형태**: LangGraph 기반 멀티 에이전트 파이프라인 + ART-cli 연동 자동 보정 데모

---

## 1. 프로젝트 개요

사용자의 요구사항(텍스트/사진 특성)을 입력받아 ART의 `.arp` 프로필을 생성하고, ART-cli로 실제 RAW 이미지를 자동 보정하는 것까지 이어지는 파이프라인. 4개 서비스(추천/요약/번역/문서QA)가 각각 독립 과업이면서, 동시에 하나의 LangGraph 에이전트로 통합될 수 있는 구조로 설계.

```
[사용자 입력: 텍스트 요청 / RAW+EXIF]
            ↓
     [LangGraph Router]
            ↓
   ┌────────┼────────┬─────────┐
   ①RAG추천  ②피드백요약  ③용어번역  ④문서QA
   └────────┴────────┴─────────┘
            ↓
     [.arp 프로필 생성]
            ↓
   [ART-cli 실행 → 자동 보정 결과물]
```

### 왜 ART인가 (차별화 포인트)
- `.arp`는 INI 스타일의 텍스트 포맷이라 LLM 기반 구조화 생성·파싱에 적합
- ART는 실제 CLI(`ART-cli`)와 외부 스크립트 확장점(`usercommands`)을 공식 제공 → 텍스트 답변에서 끝나지 않고 **실제 보정된 이미지**까지 나오는 폐쇄 루프 데모 가능
- 단, ART 개발자는 공식 문서에서 툴 자체의 전면적 AI 통합 계획은 없다고 명시하고 있음 → 본 프로젝트는 "ART 코어 확장"이 아니라 "ART를 감싸는 외부 에이전트 레이어" 포지셔닝
- 유사 선행 사례(RawTherapee/pp3 대상 AI 자동보정 CLI 툴)가 존재 → 본 프로젝트의 차별점은 (1) RAG 기반 근거 제시, (2) 4개 과업 통합 LangGraph 파이프라인, (3) RAGAS/SSIM/BLEU/ROUGE 등 정량 평가 체계

## 2. 서비스별 상세 기획

### ① RAG 기반 보정 추천

| 항목 | 내용 |
|---|---|
| 입력 | RAW의 EXIF(ISO, 셔터스피드, 카메라 모델) + 자연어 스타일 요청 |
| 출력 | `.arp` 파라미터 + 근거 설명 |
| 데이터 | **MIT-Adobe FiveK** — RAW 5,000장 + 전문가 5인(A~E)의 실제 Lightroom 슬라이더 조정값 + 씬 semantic 라벨(실내외/시간대/광원/피사체). 서브셋 200~500장으로 축소 사용 |
| 전문가 선택 기준 | 학계 컨벤션(다수 논문)은 Expert C를 단일 정답으로 사용 — 재현성/비교가능성 목적이지 미적 우월성 근거는 아님. 본 프로젝트는 용도별로 분리: **정량 평가 벤치마크는 Expert C**(비교가능성 확보), **RAG 검색 코퍼스는 5인 전체를 별도 엔트리로 포함**(스타일 다양성 확보 — 단일 전문가만 쓰면 스타일 프롬프트별 차별화된 추천이 불가능해짐) |
| 파이프라인 | FiveK 슬라이더값 → arp 파라미터 근사 매핑(컨버터 직접 설계) → 전문가-사진 렌디션마다 색공간 통계(색온도/채도/대비) 룰 또는 VLM 캡션으로 스타일 태깅 → 씬+스타일 임베딩 유사도로 유사 사례 검색(top-k) → 검색된 사례를 근거로 신규 파라미터 생성 |
| 평가 | ART-cli로 렌더링 → FiveK Expert C 결과물과 SSIM/LPIPS/ΔE 비교, 검색 단계는 context precision/recall |
| 리스크 | Lightroom↔arp 매핑이 근사치(1:1 아님) — 한계로 명시 필요. 자유형 스타일 프롬프트(예: "빈티지 톤")는 FiveK에 텍스트 라벨이 없어 룰/VLM 태깅으로 보강하거나 별도 소규모(30~50개) 세트 직접 구축. 전문가별 스타일 성향(예: "A는 웜톤 선호")은 문서화된 자료가 없어 필요시 직접 통계로 검증 필요 |

### ② Agent 기반 피드백 요약

| 항목 | 내용 |
|---|---|
| 입력 | 애매한 고객 피드백(예: "매트한 무드로") |
| 출력 | 단계별 ART 파라미터 체크리스트 |
| 전략 | **지식 증류(distillation)**: 실제 피드백 문장 소량 수집 → 큰 LLM으로 체크리스트 대량 의사 라벨링 → 50~100개는 수작업 검수 후 학습에서 제외, 평가 전용 골드셋으로 분리 |
| 모델 | KoBART + LoRA 파인튜닝 (의사 라벨 데이터 기준) |
| 평가 | 골드셋 대비 ROUGE + 파라미터명 매칭 정확도(실제 ART UI 파라미터명과 일치 여부) |

### ③ 생성형 번역 (전문 용어 + 톤 제어)

| 항목 | 내용 |
|---|---|
| 입력 | ART 영문 튜토리얼/가이드 |
| 출력 | 국내 리터처 톤앤매너의 한글 번역 + UI 용어 원문 병기 |
| 전략 | AI Hub 일반 한영 병렬 코퍼스로 warm-start → RawPedia 원문+번역(100~200문장, LLM 초안+직접 검수)로 도메인 2차 파인튜닝 |
| 모델 | mBART 또는 NLLB + LoRA |
| 용어 정확도 보장 | 파인튜닝만으로는 UI 용어 병기율 100% 보장 어려움 → 용어집 기반 제약 디코딩/후처리 치환 병행 (톤은 모델, 용어는 규칙) |
| 평가 | 골드 번역 대비 BLEU + 용어집 커버리지율 |

### ④ 문서 기반 Q&A / Agentic RAG 챗봇 (ART Master Agent)

| 항목 | 내용 |
|---|---|
| 입력 | ART 사용법 질문 |
| 코퍼스 | RawPedia 매뉴얼, README/RELEASE_NOTES, GitHub Issues(81+)·Discussions — 이미 실존하는 데이터라 4개 과업 중 데이터 리스크 최저 |
| 검색 고도화 | 쿼리 재작성, HyDE, 리랭킹 |
| LangGraph | 질문 분류(기능문의/버그/사용법) → 검색 → 필요시 재검색 → 답변 생성 |
| 고도화(기본) | 답변 기반 `.arp` 자동 생성 → `ART-cli`로 실제 렌더링까지 연결 — **4개 서비스 중 가장 완성된 데모**가 될 지점 |
| 고도화(스트레치) — 로컬 보정 자동화 | "인물 얼굴만 노출 올려줘" 같은 부분 보정 요청 지원. ART는 이미 외부 마스크 임포트를 지원하고, 공식 AI 툴 **SMART**(SAM2 기반)가 마스크를 PNG로 생성해 ART에 "external mask"로 불러오는 구조가 존재 — 마스크 생성 인프라 자체는 새로 만들 필요 없음. 단 SMART는 사람이 직접 클릭(포함/제외 포인트)하는 인터랙티브 툴이라, 완전 자동화하려면 텍스트 프롬프트→세그멘테이션(Grounding DINO로 위치 특정 → SAM2로 마스크 생성) 파이프라인으로 대체 필요 |
| 로컬 파라미터 값 추천의 데이터 문제 | FiveK는 글로벌 톤 조정만 다루는 데이터셋이라 로컬 보정용 대규모 ground truth가 없음(확인된 공개 데이터셋 없음) → ②와 동일한 지식 증류 전략(소량 실제 사례 수집 + 큰 LLM 의사라벨링 + 소규모 골드셋 수작업 검수) 재사용 |
| 평가 | RAGAS (context precision/recall, faithfulness) |

## 3. 기술 스택

- **오케스트레이션**: LangGraph
- **벡터DB**: Chroma / pgvector
- **파인튜닝**: KoBART, mBART 또는 NLLB — LoRA/PEFT (풀파인튜닝 대비 반복 실험 속도 우선)
- **컴퓨트**: RunPod RTX PRO 6000 Blackwell
- **렌더링 엔진**: ART-cli
- **세그멘테이션(스트레치)**: SAM2(SMART 연동 재사용), 텍스트 프롬프트화 필요 시 Grounding DINO
- **평가**: RAGAS, ROUGE, BLEU, SSIM/LPIPS/ΔE

| 월 | 목표 | 주요 작업 |
|---|---|---|
| 1개월차 (~60h) | 기반 구축 | arp 스키마 직접 확인(GUI export), RawPedia+Issues 코퍼스 구축(④), FiveK 서브셋 확보 및 EXIF/씬라벨 정리(①), 벡터DB 셋업 |
| 2개월차 (~65h) | ④ 완성 | 쿼리재작성/HyDE/리랭킹, LangGraph 라우팅, RAGAS 평가 — **데모 가능 상태 확보** |
| 3개월차 (~70~80h) | ① 진행 + ②③ 착수 | Lightroom→arp 매핑, 사례기반 검색+생성, ART-cli 렌더링 평가 / 후반부부터 ②③ 데이터 파이프라인(피드백 수집, pseudo-labeling, AI Hub warm-start 데이터 준비) 병행 시작 |
| 4개월차 (~65~75h) | ②③ 파인튜닝 + 통합 | KoBART/mBART LoRA 파인튜닝 완료, 전체 LangGraph 단일 에이전트 통합, CLI 연동 flagship 데모 완성, 평가 결과 정리 및 문서화 (최소 1주 확보) |

## 5. 일정 지연 시 컷라인 (우선순위 역순)

0. ④의 로컬 보정 자동화(스트레치 골) — 원래 스코프에 없던 추가 기능이라 가장 먼저 제외. 제외해도 ④ 기본 Q&A는 그대로 유지되므로 서사 손상 없음
1. ①의 ART-cli 자동 렌더링 정량 평가(SSIM/LPIPS) → 정성 비교로 축소
2. ②③ 파인튜닝 → 프롬프팅 기반 에이전트로 대체
3. ③ 전체 제외 (가장 독립적이라 서사 손상 최소)
4. ④ 기본 문서 Q&A는 코어 과업이므로 최후까지 유지

## 6. 남는 리스크 요약

- FiveK(Lightroom) ↔ arp 파라미터 매핑은 근사치 — 한계로 명시적 문서화 필요
- 도메인 파인튜닝 데이터 부족 → ②는 distillation, ③은 warm-start+소량 도메인 파인튜닝으로 우회
- 자유형 스타일 프롬프트(①) 평가셋은 소규모 직접 구축 필요
- FiveK 단일 전문가(C) 관행은 회귀 벤치마크용이라 스타일 다양성이 필요한 본 프로젝트엔 그대로 안 맞음 → 평가/코퍼스 용도 분리로 대응(2장 ① 참고)
- 로컬 보정(부분 보정) 자동화는 마스크 생성(SMART/SAM2)은 재사용 가능하나 파라미터 값 ground truth가 없음 — 스트레치 골로 격리, 일정 압박 시 최우선 제외
